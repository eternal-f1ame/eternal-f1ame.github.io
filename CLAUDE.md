# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personal portfolio for Aaditya Baranwal, forked from Once UI's Magic Portfolio (`@once-ui-system/magic-portfolio` in `package.json`). Deployed to GitHub Pages as a static export on the custom domain `sochastic.me`; `vercel.json` additionally declares a Vercel target.

## Commands

- `npm run dev`: dev server at http://localhost:3000. The only local target where the API routes exist.
- `npm run build`: static export to `./out` (Next.js `output: 'export'`); currently 20 prerendered pages.
- `npm start`: **does not work here**, because `next start` refuses `output: 'export'`. Preview a build with `npx serve@latest out` (or `python3 -m http.server` inside `out/`).
- `./deploy-to-github-pages.sh`: wraps `npm run build` and prints next-step instructions. The real deploy is `.github/workflows/deploy.yml`: Node 18, `npm ci`, `npm run build`, uploads `./out`, deploys on push to main/master.
- No test, lint, or format script is wired into npm, and Biome is not a dependency. `biome.json` is a **Biome 1.9.4** config (2-space, 100-col, double quotes); a bare `npx @biomejs/biome` fetches 2.x and aborts on the config, so pin it: `npx @biomejs/biome@1.9.4 check src/`. The tree is not Biome-clean (~138 diagnostics, mostly formatting and import order), so never run `--write`/`--fix` across the repo; format only what you touch. ESLint is installed but disabled during builds (`next.config.mjs`).

## Architecture

### Static export caveat (important)
`next.config.mjs` sets `output: 'export'`, `trailingSlash: true`, `images: { unoptimized: true }`:
- The build labels `/api/authenticate` and `/api/check-auth` as `ƒ Dynamic` and silently omits them from `out/`, with no error. On GitHub Pages this means the cookie password gate (`protectedRoutes` + `RouteGuard`) can never authenticate; it works only under `npm run dev` or on Vercel.
- Link previews are drawn at build time instead: `src/app/og/[card]/route.tsx` is a `force-static` route handler whose `generateStaticParams` lists every card in `src/app/og/cards.ts` (one per page, post, project and poem), so each becomes a real file, `out/og/<card>.png`. Its fonts are WOFF files in `src/app/og/fonts/` (Satori reads TTF, OTF and WOFF, not WOFF2). Pages build their title, description and preview through `pageMetadata()` in `src/app/utils/share.ts`; a new page or collection needs a card in `cards.ts` too, or its preview 404s.
- `trailingSlash: true` is why `RouteGuard` strips a trailing `/` before matching `routes`, whose keys are written without one.

### Content-driven model
Site copy and structural switches live in two files, not in component JSX:
- `src/app/resources/config.js`: `baseURL` (bare host, no scheme; callers write `https://${baseURL}`), `routes` (per-page on/off), `protectedRoutes`, `style` theming tokens, `display`, `mailchimp`.
- `src/app/resources/content.js`: `person`, `social`, `newsletter`, `home`, `about` (experience/studies/skills), `blog`, `work`, `publications`, `gallery`, and `site` (the site's small voice: the 404's lines in `site.notFound`, the tab title shown while the visitor is on another tab in `site.awayTitle`, read by `src/components/AwayTitle.tsx`, and the footer's `site.colophon`). The index pages take their title and the line under it from each object's `heading` and `intro`, through `src/components/PageHeader.tsx`. It is a `.js` file that **contains JSX**: many values are React nodes (`<>…</>`, `<strong>`), so they render as markup but cannot be serialized or turned into JSON. Both server pages and client components (`Header`) import it.

- `src/app/resources/palette.scss` defines the monochrome `--scheme-brand-*` and `--scheme-accent-*` ramps. `config.js` selects them with `brand: "custom"` / `accent: "custom"`, which `[data-brand="custom"]` in `src/once-ui/tokens/function.scss` maps through; `layout.tsx` imports the file after the once-ui tokens, so the vendored library stays untouched. The page light inherits these ramps too (its glow is `brand-background-strong`), so editing the ramp restyles it as well.

- `src/app/resources/glass.scss` is the glass and motion layer, global classes imported by `layout.tsx`: `.glass` (hairline edge, specular inset, backdrop blur), `.glass-sheen` (a highlight that follows the pointer), `.glass-interactive` (lift on hover, press on active), `.glass-panel`, `.glass-tile`, `.glass-button` (a light sweep, for once-ui `Button`/`IconButton` via `className`), and `a.glide-link` (a quiet text link that brightens while its trailing icon glides; written with the `a` so it matches the specificity of once-ui's `a:not(.button)` colour and hover-underline rules, which this file loads after). One easing curve and three durations (`--ease-glide`, `--glide-quick/--glide/--glide-slow`) for the whole site. Wrap a surface in `src/components/Glass.tsx` rather than using the classes bare: it writes the `--mx`/`--my` pointer position the sheen reads. Glass goes on surfaces you touch or that hold a picture (hero panel, project, post and paper cards, poem tiles, gallery tiles); lists of type (roles, community lines) stay flat, which is what keeps it from reading as wallpaper. A glass surface inside a link also lifts on the link's keyboard focus. Everything honours `prefers-reduced-motion`.

- `src/app/resources/type.scss` gives the site two voices: Inter for the interface, Newsreader (`--font-serif`, loaded in `layout.tsx` with its optical-size axis) for what is read rather than scanned. once-ui's `display-*` styles carry the serif, so page titles, section titles (`Section` uses `display-strong-xs`) and post titles turn serif while `heading-*` card titles stay Inter; `.serif` sets long text such as poems and posts. The display weights drop to 400/500 because once-ui's light/extra-bold suit a sans, not a serif. Its overrides are written `html:root`, since Next emits this stylesheet and once-ui's tokens in either order.
- `src/components/Backdrop.tsx` is the page light that replaced once-ui's `Background` effects: a soft glow and a manga screentone (three layers of one dot grid, each with bigger dots and a shorter reach, so dots swell toward the light). It trails the pointer on a fine-pointer device and rests at the top centre on touch screens; it writes only `--light-x/--light-y` and its rAF loop stops once settled. Headless Chrome reports `pointer: none`, so screenshots show the resting light unless `matchMedia` is stubbed.

Re-exported through `src/app/resources/index.ts`, imported as `@/app/resources` / `@/app/resources/content`.

### Three content pipelines
1. **MDX collections**: blog `src/app/blog/posts/*.mdx` → `src/app/blog/[slug]/page.tsx`; projects `src/app/work/projects/*.mdx` → `src/app/work/[slug]/page.tsx`. Both call `getPosts([...pathSegments])` (`src/app/utils/utils.ts`: `fs` + `gray-matter`, path resolved from `process.cwd()`, missing dir → `notFound()`), and `generateStaticParams` enumerates slugs at build time. Slug comes from the filename, so a `slug:` frontmatter key is ignored, as is any key outside the `Metadata` type (`title`, `publishedAt`, `summary`, `image`, `images`, `tag`, `team`, `link`); the current project files carry unused `stack:`/`date:` keys, and every project now sets `summary`, which is what the cards render as their description. A project is a picture card (`src/components/ProjectCard.tsx`, styles in `src/components/work/Projects.module.scss`): its first `images[]` entry (16:10 WebP under `public/projects/`, grey at rest and in colour on hover) beside the title and summary, stacked on phones, or the title set as type when it has no image. The whole card is its one "View project" link: the project's `link` when it has one, otherwise its write-up page. The write-up page shows every image and links `link` at its foot. The current pictures are the project's own material: a screenshot of the live site, figures and frames from the repo, or a drawing of the repo's own data (VOWEL's hand landmarks); blog `tag` is a comma-separated string, shown as words in a post's line of facts. A post's page (`src/app/blog/[slug]/page.tsx`, styles in `src/components/blog/Post.module.scss`) is set for reading: one column of about 66 characters, the body in the serif through its own plain `<p>` (passed as `components={{ p: Paragraph }}`; `CustomMDX` accepts any subset of its components, and project write-ups keep the once-ui paragraph), date, reading time (`readingTime()` in `src/app/utils/reading.ts`, 220 words a minute) and tags under the title, older and newer posts at the foot, and a reading-progress hairline driven by `animation-timeline: scroll(root)` where supported. Post cards (`Post.tsx`, a server component so a post's text never ships to the browser for its card) set the title in the serif with the summary and the same facts. `src/app/rss.xml/route.ts` writes the blog to `out/rss.xml` at build time, and the layout's `alternates` advertise it on every page. `Posts`/`Projects` sort by `publishedAt` desc and slice by `range`.
2. **Arrays in `content.js`**: `/publications` renders `publications.papers` (`title`/`venue`/`year` required, `authors`/`link`/`award`/`image`/`page`/`code`/`bib` optional; entries are ordered by hand, published venues first and unpublished last) directly; no MDX, no per-paper route. Both `/publications` and the landing page render the list through `src/components/publications/Papers.tsx`; `<Papers featured />` filters to the entries carrying a `featured` rank and sorts by it, so the landing page's three papers and their order are set in `content.js` (`featured: 1`, `2`, `3`) independently of the publications page order. Each paper is a picture card: `image` is a 16:10 WebP in `public/papers/` (at most 960px wide; grey and dimmed at rest, in colour on hover), `page` is the project page, which the card opens in preference to `link` (the title is the card's link, stretched over the whole card by its `::after`), and a row of small links under the venue sits above that stretched link: Paper (`link`, shown when the card opens a project page), Code (`code`: official repositories that hold real code, so a placeholder repo is left out) and BibTeX (`bib`, a `.bib` file in `public/papers/` that `CopyBibtex` copies to the clipboard, falling back to opening the file), and a paper without an `image` shows the part of its title before the subtitle, set as type. The cards wrap three, two or one across, and a short last row is centered. The current visuals are each paper's teaser: from its project page where one exists, otherwise Figure 1 of its arXiv HTML render (`arxiv.org/html/<id>`; a teaser's `<img>` often sits just before the `<figure>` that holds its caption). OpenReview refuses scripted downloads.
3. **Gallery items**: `gallery.items` mixes `type: "poem"` (a `.txt` in `public/gallery/poems/` plus a cover image in `public/assets/`) and `type: "picture"` (`src`/`alt`/`orientation` → `ImageCard`; none configured today). Every poem has its own page, `/gallery/<slug>` (`src/app/gallery/[slug]/page.tsx`), where the slug is `slugify(title)` (`src/app/utils/slug.ts`: "LORD OF BEASTS..." → `lord-of-beasts`). `getPoems()` (`src/app/utils/poems.ts`) reads the text at build time, splits it into stanzas at blank lines and lifts a closing `~ name` line off as the signature, so the words are in the HTML. The page sets the photo beside the poem in the serif, develops the photo from grey into colour, brings the stanzas in one by one, and links the previous and next poem (wrapping around). In the wide layout the photo is pinned (`position: sticky`) and the poem scrolls past it until its signature sits level with the photo's lower edge: `PoemSpread` (`src/components/gallery/PoemSpread.tsx`) measures how much foot room that takes (window height, photo height and the visitor's text size all change it) and writes it to `--room`, padding under the poem; it re-measures on resize, image load, font load and every `animationend`, and never removes room before measuring, so a reader's scroll position cannot jump. The poem's last line carries no bottom margin, so where a page already has more room than that, the photo lets go exactly as the signature meets its edge and the two scroll on together. The foot of a poem page is pinned to the bottom of the window like the header (`.dock` in `src/components/gallery/Poem.module.scss`): the previous and next poems over the footer, which the page renders itself, so `body:has(.dock) > footer` sets the layout's footer aside. On a phone the strip floats just above the bottom nav with the poems alone, and the layout's footer returns to the end of the page with room under it. The page keeps `--dock` of room at its foot so nothing ends under the strip, and the pinned photo is capped at the height between the header and the strip, so a tall photo in a short window still shows whole. The strip carries `.page-fixed`, which `.page-enter` skips: an ancestor's transform would unpin anything `position: fixed`. Gallery tiles (`PoemCard`) and the landing page's "Off the clock" tiles link there. Adding a poem = drop the `.txt` and the image into `public/`, then add the entry; its page, share card, sitemap entry and prefetch follow from the entry.

MDX rendering goes through `src/components/mdx.tsx` (`CustomMDX` via `next-mdx-remote/rsc`), which remaps `h1`–`h6` to `HeadingLink` (auto-slugged anchors, paired with `ScrollToHash`), `img` to `SmartImage`, `a` to `SmartLink`, plus custom `Table` and `CodeBlock`. A new MDX collection needs a directory, a `[slug]/page.tsx` calling `getPosts`, and a `RouteGuard` entry (see Conventions).

### Landing page
`src/app/page.tsx` is an index rather than a hero, laid out on one center axis under the nav, and it composes entirely from content: the identity block from `person` plus `home.subline` and `social`, then "Lately" (`home.lately`, news newest first, each a `date` and a `text`, drawn by `src/components/Lately.tsx` as a column of months beside what happened), then three featured papers, the three most recent `about.work.experiences`, one `Projects` card (rendered with the `flush` prop so it lines up with the section headings) plus a compact list of the remaining projects, an "Off the clock" section (the three newest poem covers, the community lines whose `about.volunteering.items` carry a `featured` rank, and the one line of prose in `home.sections.life.intro`), then two `Posts`. The identity block is a `Glass` panel with the portrait stacked above the name. Every section goes through the local `Section` helper (a short rule, the centered title, the content, then its "see all" link at the foot, which a section without `href`/`cta`, such as Lately, leaves out), and the role, project and community lists through `Entry` (a strong line over a quiet one, centered). Section labels and their "see all" links live in `home.sections`, so adding or renaming a section is a content edit. Each section is gated on its `routes` entry.

### Design system: `src/once-ui/`
Vendored Once UI library; treat it as a third-party dependency, not project code, with one deliberate exception: its `px` were converted to `em` and its root font size unpinned (see Units and breakpoints), so re-vendoring or upgrading it means redoing that conversion. ~50 components (Flex/Column/Row, Grid, Heading, Button, SmartImage, Carousel, RevealFx, Background, ToastProvider, …) from `@/once-ui/components`, `CodeBlock` from `@/once-ui/modules`. SCSS tokens in `src/once-ui/tokens/` (theme, scheme, typography, border, shadow, layout) are driven by the `data-*` attributes `src/app/layout.tsx` sets on `<html>` from `config.js` `style`. Any icon name used anywhere (`social[].icon`, `prefixIcon`, `<Icon name>`) must be registered in `iconLibrary` in `src/once-ui/icons.ts`; add the react-icons import there first. Prefer composing existing once-ui primitives; reach for `src/components/*.module.scss` only when a primitive doesn't fit.

### Layout & routing
`src/app/layout.tsx` is the single root layout: loads once-ui SCSS, wires fonts (Inter, Newsreader as `--font-serif`, Source Code Pro), applies theme `data-*` attrs, renders `Backdrop` + `Header` + `<RouteGuard>{children}</RouteGuard>` + `Footer`. `src/app/template.tsx` wraps each page in `.page-enter`, which mounts afresh on every navigation, so a page fades and rises into place on arrival. `RouteGuard` (`src/components/RouteGuard.tsx`, client component) decides during render, from the path alone: it renders `NotFound` unless the normalized path is enabled in `routes` or sits under one of the **hardcoded** `dynamicRoutes = ["/blog", "/work", "/gallery"]`, so a public page is in the static HTML and shows at once (it used to check in an effect, which put a spinner on every load and every navigation and left the exported HTML empty). Only a `protectedRoutes` page waits on the password fetch. Page titles go through the layout's template, `%s · <name>`, which Next does not apply to the layout's own page, so the landing page writes the name itself. Live pages: `/`, `/about`, `/work` (+ `/work/[slug]`), `/blog` (+ `/blog/[slug]`), `/gallery`, `/publications`. `sitemap.ts` and `robots.ts` generate from `routes` + MDX slugs. `RoutePrefetch` (client, mounted in the layout) warms the rest of the site once the browser is idle: every blog and project payload, plus the gallery covers. Top level routes are deliberately left out, since the header nav is `next/link` and Next already prefetches those; adding them again just refetches each payload under a second cache key. It backs off on saveData and 2g, and holds the images back on 3g.

On `/about`, the section index (`src/components/about/TableOfContents.tsx`) sits in the sticky portrait column under the languages, and is hidden once that column stacks above the content (`--s`). The header's location and clock hide at `--m` and below, because the labelled nav pill needs the whole width there.

Naming drift worth knowing: the route is still `/work` with MDX under `src/app/work/projects/`, but `work.label` is "Pastime" and that is what the nav and back-buttons display.

### Path aliases & assets
`@/*` → `./src/*` (`tsconfig.json`), `strict: false` but `strictNullChecks: true`, `pageExtensions` includes `.mdx` (`next.config.mjs`). Served files live in `public/` (including `public/CNAME`, the copy that lands in `out/`); the tracked `assets/` directory at the repo root holds original images/favicon sets and is **not** served.

## Units and breakpoints

- **`em`, never `px`.** Every size in `src/` is in `em` (the vendored once-ui library included; its `px` were converted at 1em = 16px, and its existing `rem` tokens kept). The only exceptions: `src/app/og/[card]/route.tsx`, which Satori renders to a PNG rather than a browser, and the numeric keys in `MasonryGrid.tsx`, which `react-masonry-css` compares against `window.innerWidth`.
- **The root follows the visitor.** `--font-scaling-*` in `src/once-ui/tokens/theme.scss` is `1em` (it shipped as a pinned `16px`, which overrode the browser text-size setting), so every `em` and `rem` on the site scales with it. Careful with `em` inside an element that sets its own `font-size`: padding there is relative to that size, as in `.glass-tile-label`.
- **Breakpoints** live in `src/app/resources/breakpoints.scss`, in `em` so the layout switches on the visitor's text size: `--xs` 30em (phones), `--s` 48em, `--m` 64em, `--l` 90em, `--xl` above. It is listed after once-ui's own file in `postcss.config.js` (`@csstools/postcss-global-data`), so these definitions win and resolve in every `.scss` without an import. The gallery runs 1 / 2 / 3 columns at `--xs` / `--m` / wider.
- **Screenshots:** headless Chrome clamps windows to a 500px minimum, so `--window-size=400` lays out JavaScript-driven layout (the masonry grid) at 500px. Use DevTools-protocol device emulation for true phone widths.

## Conventions

- Adding a top-level route takes three edits: enable it in `routes` (`src/app/resources/config.js`), add its `ToggleButton` block in `src/components/Header.tsx` (nav links are hardcoded per route, each gated on `routes[...]`), and, if it has nested pages, add its prefix to `dynamicRoutes` in `RouteGuard.tsx`, or the page 404s client-side.
- Don't put strings in component JSX when they belong in `content.js`; every other page does it that way.
- New MDX post: drop the file in the right directory with `title` + `publishedAt` frontmatter (blog entries also want `summary`); it appears automatically, sorted by `publishedAt` desc.
- Password-protected pages need `PORTFOLIO_PASSWORD` in env and a runtime target (Vercel/dev), never GitHub Pages. The single `protectedRoutes` entry today is a leftover template slug with no matching MDX file.
